## SaaS & Recurring Revenue Metrics Engine (Phase 5 Extension)

Integrate into **Phase 5 — Revenue Systems** when offer type is subscription, membership, or SaaS.

### Core metrics

| Metric | Definition | Healthy signal |
|---|---|---|
| **MRR / ARR** | Monthly/annual recurring revenue | Growing net of churn |
| **Churn rate** | % customers lost per period | Industry-dependent; trend down |
| **LTV** | Avg revenue per customer × lifespan | LTV:CAC ≥ 3:1 |
| **Activation rate** | % reaching first value milestone | >40% in 48h (benchmark varies) |
| **NRR** | Net revenue retention (expansion − churn) | >100% for scale SaaS |
| **Failed payment recovery** | % recovered after dunning | >30% recoverable |

### Retention workflow library

#### Failed payment recovery (dunning)

| Touch | Timing | Channel | Message frame |
|---|---|---|---|
| 1 | Day 0 — failure | Email + in-app | "Update card — your access continues uninterrupted" |
| 2 | Day 3 | Email | Value reminder + one-click update link |
| 3 | Day 7 | Email + SMS | Urgency — data/export window |
| 4 | Day 14 | Email | Downgrade or pause offer before cancel |
| 5 | Day 21 | Email | Win-back incentive (if margin allows) |

**Copy rules:** No shame. Lead with value at risk. One-click fix. Named support contact.

#### Onboarding activation triggers (24–48h)

| Trigger | If user… | Automated action |
|---|---|---|
| **Signup, no action** | Hasn't completed step 1 in 2h | Email: "60-second quick start" |
| **Partial setup** | Stuck on integration | In-app guide + "book 15-min install" |
| **First value** | Hits milestone | Celebration + ascension CTA (upgrade, referral) |
| **Power user** | High usage week 1 | Case study invite + community |

**Architect deliverable:** First Value Milestone definition + 5-email activation sequence.

#### Cancellation deflection flows

At churn attempt — survey → branch:

| Survey answer | Deflection offer |
|---|---|
| "Too expensive" | Pause 30 days, downsell tier, or payment plan |
| "Not using enough" | Concierge onboarding session + template pack |
| "Missing feature" | Roadmap preview + beta access |
| "Switching competitor" | Comparison doc + loyalty incentive |
| "Temporary pause" | Freeze account, keep data, resume date |

**Ethics:** Only offer what you can deliver. No dark patterns on cancel.

## Quantitative Funnel Diagnostics & Drop-Off Troubleshooting

When user provides live metrics, run the **symptom → root cause → agent solution** matrix.

| Funnel Metric Symptom | Primary Root Cause | Systemic Agent Solution |
|---|---|---|
| **High ad clicks, low opt-in** | Message mismatch: ad hook ≠ landing headline | Rewrite above-fold headline to mirror ad hook verbatim; reduce form fields to minimum |
| **High landing traffic, low checkout start** | Weak mechanism or insufficient agitation ("mice aren't big enough") | Inject New Mechanism section; re-run Carlton "So What?" benefit extraction; add proof pyramid layer 2 |
| **High checkout starts, high cart abandonment** | Sticker shock, hidden fees, purchasing anxiety | Micro-guarantees beneath CTA; split-pay or installment; free shipping threshold; order summary clarity |
| **High sales, high refund/churn** | Promise ≠ onboarding speed (expectation gap) | Redesign info-product transformation map; rapid-activation assets; week-1 quick win module |
| **Low email open rate** | Subject line / sender trust | Caples variants; re-permission campaign; proof-led subject |
| **High opens, low clicks** | Weak CTA or slippery slide break | Single hyperlinked CTA; Sugarman seed pass; one job per email |
| **Low show rate (webinar/VSL)** | Reminder sequence + commitment | SMS reminder; "show up" bonus; calendar block instructions |
| **Low close rate on calls** | Offer stack or objection handling | Hormozi stack audit; proof pyramid gap; guarantee naming |

### CRO diagnostic workflow

```
1. INGEST     — User provides metric table (symptom + numbers)
2. ISOLATE    — Identify single worst leak (Kern GOO)
3. DIAGNOSE   — Map symptom → root cause from matrix above
4. PRESCRIBE  — Specific copy/structural fix + A/B test hypothesis
5. REWRITE    — Targeted asset (headline, email, page section)
6. MEASURE    — Define success metric + minimum detectable effect
```

**Output tags:** `<diagnostic_summary>` with metric table · `<copy_draft>` with rewritten node · hypothesis in revision log.
