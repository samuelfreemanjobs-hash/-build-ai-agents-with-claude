# Framework & Workflow Engine

**The Architect's meta-craft:** design named intellectual property (frameworks) and repeatable execution systems (workflows) that teach, sell, scale, and convert — in one voice.

**Not a mode.** Framework and workflow creation is a **core competency** layered on every deliverable: courses, funnels, books, SOPs, agent systems, launch playbooks, and client operating models.

**Templates:** `research/FRAMEWORK-DESIGN-TEMPLATE.md` · `research/WORKFLOW-DESIGN-TEMPLATE.md`

---

## Framework vs Workflow (Critical Distinction)

| | **Framework** | **Workflow** |
|---|---|---|
| **What it is** | Mental model — how to *think* about a problem | Operating system — how to *do* the work in order |
| **Job** | Compress complexity → memorable structure | Eliminate decision fatigue → repeatable steps |
| **Output** | Named system with 3–7 parts, diagram, teaching spine | Phased checklist with inputs, owners, exit criteria |
| **Sells as** | Mechanism, methodology, proprietary IP | Implementation, speed, certainty, done-for-you clarity |
| **Examples in stack** | 5P Brand Loop · N×V×F · Schwartz awareness ladder · Carlton tripartite | Haines Headline→P.S. · Carlton SWS 17 steps · Galactic 9 phases |

**Architect law:** Every great framework needs a workflow to install it. Every workflow should point to the framework that makes each step make sense.

## The 7-Layer Framework Design Stack

Build bottom-up. Skip a layer → forgettable commodity.

```
7. CONVERSION ANCHOR  — CTA, offer tie-in, metric moved
6. PROOF LADDER       — case studies, before/after, audit scores
5. TEACHING SPINE    — story → reveal → install → apply
4. NAMING SYSTEM     — trademarkable name, acronym, metaphor
3. PART ARCHITECTURE — 3–7 parts (never 2, rarely 8+)
2. CORE PROMISE      — one sentence transformation
1. PROBLEM DIAGNOSIS — Schwartz + starving crowd + wrong belief
```

### Layer 1 — Problem Diagnosis

Before naming parts, nail:

- **Wrong industry belief** (the red herring — `BUSINESS-THRILLER-CRAFT.md`)
- **Mass desire** channeled (Schwartz)
- **Awareness × sophistication** — framework depth matches stage
- **Starving crowd** — urgency + ability to pay (Halbert)

### Layer 2 — Core Promise

One sentence: *"After this framework, you will [specific outcome] without [primary fear] by [mechanism category]."*

Must pass **8-word hook stress test** when compressed.

### Layer 3 — Part Architecture

| Rule | Why |
|---|---|
| **3–7 parts** | Miller's Law — working memory limit |
| **Mutually exclusive** | No overlap confusion |
| **Collectively exhaustive** | No "and also…" orphan steps |
| **Ordered or cyclic** | Linear ladder OR loop (5P, N×V×F) |
| **Verb-led names** | Actionable — Diagnose, Architect, Ship |

**Framework types (pick one primary):**

| Type | Structure | Best for |
|---|---|---|
| **Ladder** | Stages ascending | Maturity models, awareness, skill progression |
| **Loop** | Repeat cycle | Brand, content, optimization, retention |
| **Stack** | Layers build on layers | Brand stack, proof stack, offer stack |
| **Matrix** | 2×2 or 3×3 | Prioritization, positioning, audit grids |
| **Pipeline** | Input → transform → output | Funnels, product build, research-to-copy |
| **Checklist** | Linear gates | SWS, ship gate, audit protocols |
| **Diagnostic** | Questions → prescription | Executive diagnostic, GOO, Schwartz |

### Layer 4 — Naming System

Proprietary names sell mechanism at sophistication 3+.

| Element | Standard |
|---|---|
| **Framework name** | 2–4 words; ownable; searchable |
| **Part names** | Parallel grammar (all verbs, all metaphors, or all acronyms) |
| **Acronym** | Only if letters map to real words — never forced |
| **Metaphor** | One dominant image (architect, engine, ladder, flywheel) |
| **Mechanism tie-in** | Name supports product/offer positioning |

**Anti-patterns:** Generic ("The Success System"), bloated ("The 12-Step Comprehensive Holistic…"), jargon soup, duplicate industry terms.

### Layer 5 — Teaching Spine

How the framework is *taught* (not just listed):

1. **Hook story** — incongruent juxtaposition or reluctant guru (`CARLTON-METHODOLOGY.md`)
2. **Wrong belief** — what they thought was true
3. **Reframe** — why the old map fails
4. **Reveal** — name the framework (never dump in first 10% for T4)
5. **Part walkthrough** — one section per part with micro-win
6. **Application** — worksheet, audit, or 10-minute install (Pagan chunking)
7. **Ascension** — what workflow or offer completes the transformation

### Layer 6 — Proof Ladder

Each part needs at least one proof type:

| Proof | Example |
|---|---|
| Case study | Before/after metric |
| Demonstration | Worked example on real scenario |
| Audit score | Rubric dimension improved |
| Social proof | "Used by X practitioners" |
| Logic proof | Reason-why chain (Hopkins) |

Flag `[PROOF NEEDED]` — never fabricate.

### Layer 7 — Conversion Anchor

Every framework must answer: **What metric does applying this move?**

| Lever | Framework should move… |
|---|---|
| N (clients) | Lead gen, list, reach |
| V (value) | AOV, premium positioning |
| F (frequency) | Retention, ascension, repeat |

Tie to trackable CTA (Kennedy DR).

## The 8-Phase Workflow Design System

Workflows turn frameworks into **repeatable execution**. Design for humans *and* agents.

```
1. TRIGGER      — What starts this workflow?
2. OUTCOME      — Definition of done (measurable)
3. PHASES       — 3–9 phases max (cognitive load)
4. STEPS        — Checklist per phase (Haines linear discipline)
5. INPUTS       — Required artifacts entering each phase
6. OUTPUTS      — Artifacts produced + where saved
7. GATES        — Exit criteria before next phase (no skip)
8. METRICS      — Leading + lagging indicators per phase
```

### Workflow Design Rules

| Rule | Implementation |
|---|---|
| **Linear default** | Headline → P.S. order; no parallel paths unless sub-workflows |
| **Gate every phase** | Checklist ≥ 80% or explicit exception logged |
| **One owner per phase** | Role named (strategist, copywriter, editor, client) |
| **Time-box optional** | SLA when speed matters (launch sprints, 90-day celebrity) |
| **Agent-compatible** | Phases map to `architect_set_phase` when automating |
| **Revision loops capped** | Max 3 REVISE cycles (`AGENT.md`) |
| **Ship gate terminal** | Last phase always includes quality rubric |

### Workflow Types

| Type | Phases pattern | Example in stack |
|---|---|---|
| **Creation** | Research → Plan → Draft → Edit → Ship | Galactic agentic loop |
| **Audit** | Gather → Score → Prescribe → Prioritize | Phase 9 master audits |
| **Launch** | Pre-frame → Indoctrinate → Convert → Ascend | Kern IBB / PLC |
| **Build** | Diagnose → Architect → Wire → Test → Deploy | Funnel architecture |
| **Daily/weekly** | Collect → Synthesize → Apply → Log | Daily headline learning |

### Sub-Workflow Composition

Large workflows nest smaller ones:

```
GTM LAUNCH WORKFLOW
├── Executive Diagnostic (sub-workflow)
├── Funnel Architecture (sub-workflow)
├── Content 30-Day (sub-workflow)
├── Copy SWS (sub-workflow)
└── Master Audit (sub-workflow)
```

**Rule:** Parent workflow references child by name + template path — never duplicate step lists.

## Framework + Workflow Integration Patterns

### Pattern A — Framework First

1. Design framework (7-layer stack)
2. Derive workflow (one phase per framework part + bookends)
3. Build teaching assets (slides, worksheets, copy)

*Best for:* courses, books, methodology products.

### Pattern B — Workflow First

1. Map current messy process (as-is)
2. Extract implicit framework from repeated decisions
3. Name and package for sale/teach

*Best for:* agency SOPs, client delivery systems, ops consulting.

### Pattern C — Parallel Build

1. Problem diagnosis (shared)
2. Framework parts + workflow phases drafted together
3. Cross-check: every part has ≥1 workflow step; every step maps to a part

*Best for:* GTM systems, agent orchestration, launch playbooks.

## Quality Gates (Framework & Workflow)

### Framework Audit (before ship)

- [ ] 3–7 parts; mutually exclusive + collectively exhaustive
- [ ] Ownable name; not generic industry jargon
- [ ] Core promise = one sentence; passes 8-word compression
- [ ] Teaching spine: story before reveal (T4: not in Ch 1)
- [ ] Each part has proof type assigned
- [ ] Conversion anchor: N, V, or F identified
- [ ] Diagram spec included
- [ ] Schwartz stage appropriate (don't over-engineer for stage 1)

### Workflow Audit (before ship)

- [ ] Trigger + definition of done explicit
- [ ] 3–9 phases; each has exit gate
- [ ] Inputs/outputs named per phase
- [ ] Owner per phase (human or agent role)
- [ ] Sub-workflows linked, not duplicated
- [ ] Metrics: leading + lagging per phase
- [ ] Revision cap documented
- [ ] Terminal ship gate with rubric

## Swipe Patterns (Structural)

**F-001 — Acronym ladder:** Each letter = phase verb (e.g., D.A.R.T. — Diagnose, Architect, Run, Test)

**F-002 — Numbered promise:** "The 5 Locks" / "3 Pillars" — odd numbers feel complete; 3 and 5 strongest

**F-003 — Metaphor map:** One domain metaphor (construction, medicine, flight) mapped consistently

**W-001 — Gate checklist:** Phase cannot advance until ☐ checklist complete

**W-002 — Input/output contract:** "Enters with X, exits with Y" per phase

**W-003 — Agent state machine:** Phases = `architect_set_phase` values; gates = `architect_ship_gate`
