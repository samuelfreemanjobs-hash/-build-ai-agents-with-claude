Page 1 — The Slop Detector

Five failure modes that kill AI copy — and the DR fix for each.

Failure Mode #1: No Named Mass Desire

AI writes features. Buyers move on pre-existing desire. Fix: Open every asset by naming the drive already in the market (Schwartz) — not your product.

Failure Mode #2: Wrong Awareness Level

Product-aware copy sent to problem-aware prospects = instant bounce. Fix: Tag the prospect stage before drafting. Match headline to stage.

Failure Mode #3: Mechanism Missing

"We use AI" is not a mechanism. Fix: Name your system (e.g., "4-Agent DR Stack," "7-Gate Scorecard"). Own a process, not a tool.

Failure Mode #4: Proof After Claim

AI stacks adjectives. DR stacks evidence. Fix: Every claim gets a proof line before the next claim. No exceptions.

Failure Mode #5: Multiple CTAs

AI loves options. Conversion loves one fork. Fix: One action per asset. Trackable. Repeatable.

Slop test: Read your last email aloud. If you hear three product features before one buyer desire — you're shipping slop.

Page 2 — The 7-Gate DR Scorecard

Pass all seven before anything ships. Score each gate 1–10. Average ≥ 8 or rewrite.

Gate 1 — Mass desire: Is a pre-existing market drive named in the first 100 words?
Gate 2 — Awareness match: Does the headline meet the prospect where they actually are?
Gate 3 — Mechanism: Is there a named system (not a feature list)?
Gate 4 — Proof stack: Does evidence precede each major claim?
Gate 5 — Single CTA: One action only — is it obvious and trackable?
Gate 6 — Slippery slide: Does each line pull to the next (Halbert)?
Gate 7 — Ship gate: Would you stake your reputation on this asset?

Install rule: No asset publishes without a written score. Agents can draft; humans (or score agents) gate.

Page 3 — The Agent Handoff Map

Research → Draft → Score → Ship. Four roles. One pipeline.

  1. Research agent — Inputs: offer, avatar, competitor URLs. Outputs: mass desire statement, awareness level, proof inventory, objection list.
  2. Draft agent — Inputs: research brief + template (email/ad/page). Outputs: v1 copy wired to DR structure (not "creative").
  3. Score agent — Inputs: v1 + 7-Gate Scorecard. Outputs: gate scores, rewrite instructions for any gate < 8.
  4. Ship agent — Inputs: approved v2. Outputs: formatted asset + UTM-tagged CTA + archive entry.

Handoff rule: Each agent gets one job. No agent "does everything." That's how you beat the midnight edit loop.

Page 4 — The 48-Hour Deployment Plan

One free weekend. One live offer. One asset shipped with a scorecard.

Hour 0–4: Pick the asset

Choose ONE: welcome email, retargeting ad, or landing page hero. Not all three. One win beats three drafts.

Hour 4–12: Run Page 1 on your draft

Highlight every slop failure mode. Rewrite openings first — desire before product.

Hour 12–24: Score with Page 2

Gate by gate. Anything below 8 gets rewritten, not " tweaked."

Hour 24–36: Wire the handoff (Page 3 lite)

Even without full agents: separate research notes, draft doc, and score sheet into three files. Simulate the pipeline.

Hour 36–48: Ship + tag

Publish. Log the score. One CTA. One metric. That's your first intelligence system — not a prompt.
